# 28 Oktober 2026 — Electron 42.3.3 → 45.1.0 di repo; rilis 4.4.0 menunggu uji chat & PDF (T20)

Sisa T20 ("Black October"): Electron 42 **habis dukungan 20 Okt** (jadwal resmi `releases.electronjs.org/schedule`)
dan Node bawaannya rentan Brotli CVE-2026-111497. Rilis Electron **27 Okt** membawa Node 24.22.1 (tertambal):
43.8.4, 44.10.0, 45.1.0 — catatan rilis 45.1.0: *"Updated Node.js to v24.22.1"*. Owner memilih **45.1.0**
(Chromium 156, didukung sampai 27 Apr 2027).

## Analisis sebelum memasang

27 breaking change Electron 43–45 dicocokkan dengan `frontend/electron/`:

- **Tidak mengenai kita:** preload ber-sandbox kehilangan `Buffer`/`setImmediate` & `ipcRenderer` jadi EventEmitter
  native (45) — `preload.cjs` hanya `require('electron')`, tanpa global Node; anak `window.open` (45) — semua ditolak;
  `clipboard` di renderer & API Promise (44), `safeStorage` sinkron, izin `display-capture`, `contentTracing`,
  `getUserMedia` — tidak dipakai; 32-bit dihapus (44) — build hanya x64; modul native: `@napi-rs/canvas` (N-API).
- **Mengenai, kecil:** dialog pilih folder (3 tempat, tanpa `defaultPath`) kini dibuka di **Downloads** (43).
- **Dibuktikan, bukan diasumsikan:** deskriptor berkas di dalam ASAR (45) — lewat aplikasi hasil kemas (di bawah).

## Yang dibuat

- `npm install --save-dev electron@45.1.0` (`^45.1.0`). **Cara pasang Electron berubah:** paket tidak lagi punya
  `postinstall`; biner diunduh saat `require('electron')` pertama (`install.js`, diperiksa terhadap `checksums.json`
  bawaan paket). Lima paket lama (`extract-zip` dkk.) hilang dari lockfile, `@electron-internal/extract-zip` masuk.
- `ambilWeb.cjs`: komentar — Node kini tertambal, tetapi jalur `net.fetch` + penjaganya SENGAJA dipertahankan.
- Versi aplikasi **tidak** dinaikkan (keputusan Owner B): rilis 4.4.0 sesudah chat & PDF teruji.

## Bukti

- Biner: **Electron 45.1.0 · Node 24.22.1 · Chromium 156.0.8078.49** (dari `process.versions`).
- **Suite penuh 122/122** di Electron 45, termasuk uji yang menjalankan Electron sungguhan (`uji-ambil-web`,
  `uji-cangkang-electron`, konektor). Mutasi `ambilWeb` **6/6 tetap menggigit**; tanpa `credentials: 'omit'`
  `net.fetch` di 45 tetap MENGIRIM cookie sesi (sama dengan 42).
- **Aplikasi hasil kemas** (`vite build` → postbuild → bundel crawler → `electron-builder --win --dir`, tanpa publish):
  dari dalam paket — Electron 45.1.0/Node 24.22.1; `ambilWeb.cjs`, `main.cjs` (`ambilWeb(net.fetch`), `dist/index.html`
  terbaca dari `app.asar`; `crawler-runtime` membawa curl_cffi 0.17.0 & certifi 2026.10.23. Dijalankan dengan jendela:
  `mamet://app/index.html` "Mamet OS", Kernel PHASE 0 → **PHASE 10 Completed**, **0 `[Renderer ERROR]`**; lalu ditutup.
- **Uji Owner di `npm run desktop` (Electron 45):** tema ✅, sakelar konektor Assistant & Engineer ✅, workspace
  Engineer ✅, dialog pilih folder ✅. Chat & PDF ⏳ — saldo OpenRouter kosong. Sebagian jalur jaringan ikut terbukti:
  unggahan Owner ke workspace "sejarah aplikasi mamet ecosystem" sampai ke server dan galat 402 tampil benar
  ("dokumen dibatalkan"); diperiksa di database: workspace itu **0 dokumen, 0 potongan** — tak ada sisa yang akan
  membuat unggahan ulang "dilewati (judul sudah ada)".

## Catatan untuk build berikutnya

- `electron-builder` punya cache sendiri: build lokal **mengunduh ulang** `electron-v45.1.0-win32-x64.zip` (158 MB)
  walau `install.js` sudah mengunduhnya. Di GitHub hal itu terjadi tiap build (mesin bersih) — sama seperti sebelumnya.
- Build lokal `--dir` ±10 menit (unduhan, dependensi native untuk Electron 45, salin bundel crawler ±230 MB).

## Sesudah push: build rilis terpicu tanpa kenaikan versi — dibatalkan, lalu pemicunya diperbaiki

Push `635451f` (hanya versi Electron di `package.json`, versi aplikasi tetap 4.3.2) memicu **Build and Release**
(run 40621759853): `build.yml` memakai `paths: frontend/package.json`, yang hanya tahu BERKAS berubah, bukan baris —
komentarnya ("hanya build kalau ada perubahan versi") tidak benar. Tanpa intervensi, build itu akan menerbitkan isi
Electron 45 bernomor 4.3.2 ke rilis yang sudah terbit (bertentangan dengan keputusan B). **Dibatalkan** saat langkah
"Siapkan .venv crawler"; build & publish `skipped`; aset rilis v4.3.2 diperiksa lewat API — stempel 01:20Z tak berubah.

Perbaikan (`build.yml`): job baru **`periksa-versi`** membandingkan `version` di `frontend/package.json` sebelum
(`github.event.before`) dan sesudah push; job `build` `needs` + `if` hanya bila naik. Jalankan manual & cabang baru →
build. Versi sebelum push tak terbaca → **merah & berhenti** (bukan dianggap naik — celah itu ketahuan saat uji lokal).
Diuji lokal dengan blok `run` yang sama persis dari YAML: versi sama → `naik=false`; 4.3.1→4.3.2 → `true`; manual →
`true`; cabang baru → `true`; commit tak ada → kode 1. `uji-konektor-komponen` v7 menjaga kabel `needs`/`if` dan
gagal-tertutup (2 mutasi menggigit). Pembaruan otomatis tak berubah: ia memang hanya bergerak bila versi naik.

Keputusan Owner di diskusi yang sama: pemasang NSIS yang tampil saat pembaruan **tidak diubah** jadi diam-diam
(`quitAndInstall(false, true)` + `oneClick: false` tetap) — transparansi; lamanya pasang = folder aplikasi diganti utuh
termasuk bundel crawler ±230 MB.

## Menunggu (rilis 4.4.0)

Sesudah saldo OpenRouter diisi: chat (jawaban mengalir) & baca PDF di `npm run desktop` → naikkan versi 4.4.0 →
build GitHub → Publish Owner.
