# 28 Oktober 2026 — Rilis 4.3.2: paket keamanan "Black October" (T20) + bundel crawler ber-hash

Owner meminta rilis berikutnya mengusung pembaruan yang SEKELOMPOK. Kelompoknya "Black October"
([T20 bagian 1](./2026-10-27-black-october-brotli.md)). Saat memeriksa sisa yang berkaitan, ditemukan dua celah lagi
dari pekan yang sama — keduanya di bundel crawler yang sudah terpasang di laptop lain sejak 4.3.0.

## Temuan baru (diukur di `.venv` crawler)

| Paket | Sebelum | Masalah | Sesudah |
|---|---|---|---|
| `curl_cffi` | 0.16.3 — libcurl 8.21 **`brotli/1.2.0`** | CVE-2026-111497 (tertambal di brotli 1.2.1). Tingkat 2 crawler mengambil situs pihak ketiga dengan sidik jari Chrome dan meminta `br`. | **0.17.0** (26 Okt) — libcurl 8.23 **`brotli/1.2.1`**; catatan rilisnya menyebut CVE ini & eMudhra |
| `certifi` | 2026.10.19 — 3 akar emSign (eMudhra) | dipakai `requests`, `httpx`, `curl_cffi` | **2026.10.23** — tinggal "emSign Root CA - G1" (keputusan pengelola certifi) |
| kunci bundel | versi terkunci + `--no-deps`, **tanpa hash** | pelajaran LiteLLM 1.107.0: pip menerima berkas apa pun yang diberi indeks untuk versi itu | **86 paket, 172 hash** + `--require-hashes` di `build.yml` |

Aman tanpa perubahan (diperiksa): `requests`/`httpx` tidak mengurai Brotli (paket `brotli` tak terpasang; tingkat 1
meminta `gzip, deflate` saja); Chromium Patchright (stealth) = 156, sesudah perbaikan (M148).

## Yang dibuat

- Unduhan (izin Owner): `curl_cffi-0.17.0-cp310-abi3-win_amd64.whl` 2,01 MB, `certifi-2026.10.23-py3-none-any.whl`
  0,13 MB; sha256 dicocokkan dengan catatan PyPI sebelum dipasang (`--no-index --no-deps` dari folder unduhan).
  `cffi` 2.1.1 sudah memenuhi syarat 0.17.0 — tak ada paket lain ikut.
- `pyproject.toml`: `curl_cffi==0.17.0`.
- **`capability/ecosystem-crawler/scripts/kunci_bundel.py`** (baru): menulis ulang `requirements-bundel.txt` dari
  `pip freeze --all` .venv + digest sha256 PyPI, hanya berkas yang bisa dipasang Python ini (tag wheel cocok, atau
  sdist); tak mengunduh paket. `--periksa` = bandingkan saja. Daftar tidak lagi disunting tangan.
- `build.yml`: `pip install --no-deps --require-hashes`.
- `uji-konektor-komponen` v6: pembaca daftar ber-hash; setiap paket wajib ber-hash & tanpa opsi asing; `build.yml`
  wajib `--require-hashes`.
- Versi **4.3.1 → 4.3.2**.

## Bukti

- `curl_cffi` di **runtime terbundel** (`frontend/build/crawler-runtime`, yang dikemas pemasang): `brotli/1.2.1`;
  `komponen.json` mencatat curl_cffi 0.17.0 & certifi 2026.10.23.
- Tingkat 2 lewat kode sungguhan (`AksesWeb.ambil`): server lokal menolak identitas crawler (403) → naik ke
  `curl_cffi` → halaman `Content-Encoding: br` diurai utuh (200/200). Situs nyata: Bing RSS mengirim `br`, terurai.
- pip menegakkan hash: daftar asli → terpasang; satu hash diubah → `THESE PACKAGES DO NOT MATCH THE HASHES`.
- Mutasi `uji-konektor-komponen` **3/3 menggigit** (tanpa `--require-hashes`; satu paket tanpa hash; opsi asing).
- pytest crawler 39/39; **suite penuh 122/122**.

## Jabat tangan pertama 11–13 s — diselidiki, bukan dari pembaruan

`npm run crawler:siapkan` mencatat 11,3 s lalu 13,3 s (4.3.1: 3,9 s). Diukur per tahap: diulang = 1,8–3,3 s. Impor
dingin di salinan segar: seluruh server 2,7 s (sebagian besar pustaka `mcp`), **`curl_cffi` 0,06 s** (DLL 5 ms). Jadi
selisihnya biaya jalan pertama berkas yang baru ditulis (kemungkinan besar pemindaian Windows), bukan `curl_cffi`
0.17.0. Pembanding adil = build GitHub (mesin bersih; 4.3.1: 1,1 s) — diperiksa sebelum Owner menekan Publish.
